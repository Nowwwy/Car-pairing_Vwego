# CarPairing 0.16.1 실행 안정화

검증일: 2026-11-15. PC: KYSDESKTOP. 배포본 버전: 0.16.1. 앱/APK는 0.16-optimized(versionCode 21), 서버는 3.3-optimized를 유지합니다. 이번 수정 범위는 Python 두 차량 실행기입니다.

## 재현된 문제와 수정

- 기존 실행기는 sys.boot_completed=1이면 앱을 바로 열었습니다. 실제 로그에서 기본 내비가 21:43:02 시작된 뒤 응답 지연(ANR)으로 21:44:00 종료됐고, 21:44:01 재시작하면서 이미 열린 CarPairing 화면을 덮었습니다.
- Pleos 2.1의 naviReadyStatusFlow에서 AuthComplete, NaviEngineComplete, MapComplete를 모두 확인합니다. 동일 프로세스가 6초간 준비 상태를 유지한 뒤 진행하며 재시작/연결 실패 시 대기 시간을 초기화합니다. 두 차량의 준비 절차를 마친 다음 두 CarPairing 화면을 한 번씩 엽니다. `am start -W`로 실제 화면 표시까지 기다리며, 실행 요청을 보낸 것만으로 준비 완료로 처리하지 않습니다.
- 준비 확인 기준 시간은 차량당 120초이며 진행 중인 ADB 요청 때문에 최대 10초 더 걸릴 수 있습니다. 로그가 회전했거나 SDK 로그 형식이 바뀌어 확인되지 않으면 경고 후 앱을 엽니다. 따라서 모든 SDK 버전에서 내비 준비를 보장하는 방식은 아닙니다.
- 앱 실행 후 화면을 계속 강제로 앞으로 가져오는 감시 루프는 없습니다. 사용자가 기본 내비를 열 수 있습니다.
- 기존 GPS 루프는 ADB의 시간 초과/연결 오류가 발생하면 전체 실행기가 종료될 수 있었습니다. 차량별 예외를 처리하고 다음 차량을 계속 갱신하며 복구 시 다시 전송합니다. 오류/복구 상태가 바뀔 때만 로그를 남깁니다. 위치 전송은 건당 3초로 제한합니다.

## 자동 검증

- 새 회귀 검사 실패를 확인한 뒤 수정했습니다.
- 준비 전 상태, 최신 상태 우선, 프로세스 재시작, 준비 시간 초과, 일시 연결 오류 복구, 한 차량 오류 시 다른 차량 갱신, 두 내비 준비 후 앱 실행 순서를 검사합니다.
- 실행기 테스트 10개 통과. Windows 전체 Python 테스트 213개 통과(상속에 의한 반복 실행 포함).
- Android 소스/APK는 수정하지 않았습니다. Android 38개 통과 결과는 0.16 검증 기록이며 이번에 다시 실행한 결과가 아닙니다.

## 기본 내비의 흰 지도 조사

- 현재 내비 로그가 가리키는 스타일: https://a.tile.static.maps-coral.umos.ai/styles/42dot/connect_empty
- 해당 응답의 source는 coastline이며 layers는 background, coastline(fill), driving_carpet(slot), driving_carvatar(slot) 네 개입니다. 이 스타일 JSON 자체에는 도로/건물 레이어가 없습니다.
- 내비의 인증 성공 및 NaviEngineComplete/MapComplete를 확인했습니다. 따라서 단순히 인증 대기 또는 GPU 초기화 실패로 단정할 근거는 없습니다.
- 이 결과는 흰 배경의 주요 진단 단서입니다. 내비가 런타임에 추가하는 레이어/SDK 구성까지 확정한 것은 아니며, 외부 내비 지도 배경을 복구했다고 주장하지 않습니다. 해당 앱의 설정/자산/계정은 임의로 바꾸지 않았습니다.
- CarPairing 자체 지도, 목적지 적용, 차량 간 메시지는 기존 0.16 구현을 유지합니다. 실시간 빈자리/교통 정보, 지연 발화의 ETA 자동 가산, 실제 마이크·실차 검증 범위도 그대로입니다.

## 최종 실제 재시작 확인

- 두 에뮬레이터를 종료하고 스냅샷 없이 다시 시작했습니다. 두 차량 모두 준비 시간 초과 경고 없이 native navigation ready를 확인했습니다.
- 앱 실행 직후부터 10초 간격으로 60초까지 검사: 두 차량 각각 7회, 총 14회 모두 CarPairing이 topResumedActivity에 있었습니다. 화면 캡처에서도 자체 도로 지도, 두 차량 경로와 ETA를 확인했습니다. 단일 PC의 최종 재시작 1회 검증이며 모든 환경의 장기 안정성 보장은 아닙니다.
- 기존 모임 481806과 목적지(리더 투썸플레이스, 팔로워 주차장 OSM 28234)를 유지했습니다. 이전 테스트의 미응답 만차 제안도 유지되어 리더 화면에서 확인됐으며, 현재 경로 유지로 닫았습니다.
- 서버 8766 health 정상, 실행 중인 실행기 소스 두 파일과 배포 파일의 SHA-256 일치 확인.
- 첫 검증에서 앱 실행 요청과 화면 표시 사이의 시차를 발견하여 화면 표시 대기를 추가했습니다. 재검증 도구도 이전 실행 로그를 새 실행의 완료로 잘못 읽지 않도록 초기화했습니다. 위 14회 결과는 최종 코드의 현재 실행 로그를 기준으로 한 결과입니다.
- 목적지 변경·만차·지연의 전송 기능은 이번에 다시 전체 시나리오를 수행한 것으로 표시하지 않습니다. 해당 실동작 검증은 0.16 기록을 참조하세요.
