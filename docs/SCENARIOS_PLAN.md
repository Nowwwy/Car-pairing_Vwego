# 기획서 4번 구현 범위

기준: 첨부한 1차 기획서 4절의 시나리오 A와 B. 기존 ai.carpairing.app Kotlin 앱을 확장한다. 기존 3D 콘솔이나 예전 WebView 프로젝트로 교체하지 않는다.

1. 6자리 모임 코드와 목적지 좌표를 공유하고 참여 수락 후 NaviHelper에 같은 목적지를 요청한다.
2. FusedLocation에서 받은 차량 위치, NaviHelper가 확인한 개인 안내 목적지의 ETA를 공유한다. 도착 여부를 위치 또는 운전자 확인으로 판단한다. 오래된 차량 데이터는 표시를 구분한다.
3. Pleos SpeechToText/TextToSpeech로 음성 입력과 일행 발화 읽기를 연결한다. 등록 자격 증명이 없는 현재 환경은 ON_DEVICE를 사용한다. 서버 HYBRID 등록은 별도 조건이다.
4. 상황 분류는 로컬 AI를 시도하고 실패 시 기본 분류임을 표시한다. 전송자, 숫자, 불확실성을 보존한다.
5. 미도착 차량에 만차/휴식 제안을 전달한다. 운전자가 수락하고 실제 장소를 고른 경우에만 Pleos 경로를 바꾼다. 변경 확인 전에는 성공 메시지를 보내지 않는다.
6. 앞차가 고른 휴게소 좌표를 메시지에 포함해 뒤차가 같은 장소를 경유지로 추가하거나 기존 목적지로 계속 갈 수 있게 한다.
7. Vehicle SDK에서 주차 상태를 읽어 상세 입력을 제한하고 주행 중에는 음성/짧은 응답을 제공한다.
8. SDK/API 출처, 실제 검증 범위와 남은 제약을 최종 구현 안내에 기록한다.

검증: 서버 동작 테스트, Android 빌드, Pleos 에뮬레이터 두 대 설치·재실행, 실제 앱의 모임·메시지·음성 출력·위치/ETA·수락 및 거절·경로 변경 확인. 검증하지 못한 항목은 통과로 기록하지 않는다.
