오프라인 지도 시험은 이미 본 지역의 타일 보관·복원 검증이다. 새 전국 지역의 오프라인 지도를 보장하지 않는다. ADB reverse로 연결한 로컬 모임 서버까지 차단한 시험은 아니므로 “오프라인에서도 차량 간 인터넷 통신 가능”이라는 뜻도 아니다. 동봉된 대체 도로 데이터는 서울 남부·판교의 실제 OSM 도로 10,826개이며 제한된 지역만 포함한다.

SDK 경유지 조회는 해당 에뮬레이터에서 이름과 좌표 0,0을 반환했다. 따라서 앱의 적용 확인은 이름 일치를 사용했다. 내비 내부 경로 로그에는 요청한 성남졸음쉼터 좌표가 포함되었으나, SDK가 정확한 좌표를 응답했다고 주장하지 않는다.

## 경로 이상 신고 수정·재검증

신고 화면의 우회는 앞선 시나리오 검증 후 남겨 둔 성남졸음쉼터 경유지와 2번 차량의 OSM 주차장 목적지에서 발생했다. 검증을 마친 뒤 기본 경로로 복구하지 않은 상태였다.

`더보기 → 경유지 지우고 모임 목적지로 → 경유 없이 안내` 기능을 추가했다. Pleos SDK로 경유지를 순서대로 삭제한 뒤 모임 목적지를 요청한다. 목적지가 이미 같아도 경유지 삭제를 생략하지 않는다. SDK의 목적지 일치와 빈 경유지 목록을 모두 확인한 뒤에만 복구 완료를 표시한다. 다른 차량은 자동으로 바꾸지 않는다.

두 에뮬레이터의 실제 버튼을 눌러 복구 완료를 확인했다. 최종 APK 설치·앱 재실행 후에도 양쪽 목적지가 강남역 2번 출구이고 경유 표시가 사라진 것을 확인했다. 두 화면의 지도와 경로를 스크린샷으로 직접 확인했다.

| 차량 | 경유 없는 도로 거리 | 경로 응답 시간 | 화면 표시 |
|---|---:|---:|---:|
| 1번 판교 | 14,388m | 760.1초 | 13분 |
| 2번 잠실 | 10,191m | 662.5초 | 12분 |

외부 경로 공급자는 기존 FOSSGIS/OSRM을 유지했다. 두 응답의 끝 좌표는 모두 강남역 2번 출구 인근 127.028061/37.497213이다. 실시간 교통을 반영한 최적 경로 검증은 아니다. 최근 앱 로그에서 FATAL EXCEPTION은 없었으며 두 차량의 전경 서비스가 유지됨을 확인했다.

최종 설치 APK SHA-256: `811c26c032ba46e703014f7cb4e662d09c9899d7f5523e91f0d0f49a3b9a1fe1`.

## 자동 검사 결과

- Python 전체 71개 통과: 실제 로컬 HTTP/SQLite를 사용하는 네 차량 그룹, 독립 위치·ETA, 인증, 도착 차량 제안 제외, 동의/거절, 메시지 정리, 서버 재로드, 경로·주유·휴식 체류 시간 계산 등.
- Android/JVM 전체 32개 통과: 여정 동의 단계 7, 지도 디스크 캐시 5, 도로 ETA 7, 일행 ETA 2, SDK 준비 상태 2, 기존 확장 규칙 3, 음성 재생 순서 3, 경유지 삭제·목적지 복구 3.
- assembleDebug / testDebugUnitTest 성공. 실차 검증 또는 네 AVD 동시 실행 검증은 아님.
- 음성 재생 순서 테스트는 3개 실패를 확인한 뒤 구현, 모두 통과. 중지 콜백 전 새 음성 재생 방지와 중복 안내 제거를 검사.

## 음성에 대한 현재 판단

Pleos SpeechToText/TextToSpeech 3.3.1 ON_DEVICE를 사용한다. SDK 초기화 및 TTS 재생 시작은 관측했다. 사용자가 깨짐을 보고했고, 로그에서 초기 AudioTrack underrun과 두 AVD의 동시 재생을 관측했다. 일부 합성 구간의 underrun count는 0이어서 이것만으로 전체 음질 원인을 확정하지 않는다.

한 차량만 출력하도록 설정하고, 동일 프롬프트 반복 및 음성 중단/인식 시작 순서를 정리했다. 사용자가 테스트 음성을 듣지 못했다고 응답했으므로 청감 개선은 미확인이다. 실제 마이크·사투리·주행 소음 인식률도 미검증이다. 음성 설정 메뉴의 테스트 버튼으로 다시 확인할 수 있다. TTS 출력 끄기는 STT 입력과 메시지 표시를 끄지 않는다.

Pleos 서버 기반 HYBRID/TTS/STT로 바꾸려면 Pleos 프로젝트의 Client ID와 Client Secret 등록이 필요하다. 현재는 그 인증 정보를 사용하지 않는다. 임의의 외부 음성 API나 유료 계정을 새로 연결하지 않았다.

## 기획서와 남은 범위

기획서 4번 A/B의 모임·동의·위치/ETA·지연 제보·만차 대안·동일 휴게소 수락 흐름을 구현했다. 실제 화면 검증은 두 차량, 여러 명은 네 차량 HTTP 통합 검사다. 네 실차 또는 네 AVD로 A 전체를 끝까지 실행하지는 않았다.

선택 이력 추천은 사용자 동의 후 수락 기록의 빈도·최근성을 사용하는 순위다. 임의 경로 이탈을 자동 학습하는 AI 모델 재학습은 구현 완료가 아니다. 기획서 5-4의 추적 모드·공평한 중간 만남·차량 상태 자동 공유·동승자/휴대폰 참여·정산은 후속 범위이며 미완료다.

Pleos 기본 내비 자체의 지도 서버/라이선스 문제를 해결한 것이 아니라 앱의 별도 지도 경로를 보강했다. 모든 네트워크·전국 지도·실차 상황에서 오류가 없다고 보장하지 않는다.
