# CarPairing 0.15 통합 설계 및 실행 계획

목표: v0.14.3 지도·차량 ETA UI를 유지하면서 macOS 0.13.1의 음성 선택 흐름과 실행 도구에서 유용한 부분을 보완한다. 사용자가 구현 선택을 위임했으므로 기존 Python 표준 라이브러리 서버와 Kotlin/Pleos 구조를 유지한다.

비교 결과: 전국 장소 스냅샷, 의도 해석, 번호 선택 규칙은 이미 통합되어 있다. Mac APK를 덮어쓰면 기존 기능을 잃으므로 가져오지 않는다. 누락된 경로 완료 공유, OS에 종속된 실행기, 경유지 없는 경로 비교를 개선한다.

1. [x] Windows/macOS/Linux 실행 도구: SDK/ADB 탐색, 현재 Android 사용자 선택, 환경 점검, 빌드, 서버 실행, 명시적 기기 설치. 기존 두 차량 GPS 실행기는 유지하고 경로 탐색을 공용화한다. 테스트: 공백 경로, OS별 실행 파일, 기기 모호성, 서버 버전 불일치. APK가 없으면 빌드 단계 안내.
2. [x] 여러 경로 비교: 최대 두 경유지와 정차 시간 포함, 빠른 경로/짧은 거리 라벨, 지도 미리보기, 잘못된 제공자 응답은 명확한 오류. API는 origin/destination/stops를 받고 routes에 total_seconds/delta_seconds/labels를 추가. 테스트: 경유지 좌표 전달, 10분 체류, 중복/불량 응답, 권한.
3. [x] 음성 연동: 음성 선택 후 SDK가 적용을 확인하면 장소를 포함한 완료 메시지를 한 번 전송. 실패 시 같은 요청 ID로 재시도. 확인된 자신의 최근 변경을 바탕으로 '일행에게 경로 변경했다고 말해줘'를 구체화하고, 확인된 변경이 없으면 되묻는다. UI에서 AI/기본 처리 출처와 재질문을 표시. 텍스트 요청도 동일한 의도 처리 경로 사용.
4. [ ] 회귀 테스트, Windows Android 빌드 및 유닛 테스트, 실행 환경 점검, 사용법/검증 기록, 소스·APK ZIP 배포. 실제 마이크 발화와 실차 검증은 별도 명시.

제약: 기존 모임·데이터·개인 설정 보존. 사용자의 실행 중인 프로젝트를 덮어쓰지 않는 별도 폴더에서 빌드. 자동 다운로드 모델 변경 없음. 실시간 교통은 구현됐다고 표시하지 않는다. 비교 경로를 Pleos에 강제 적용하지 않는다. 장소/ETA를 지어내지 않는다. 전달 완료는 실제 전송 성공일 때 표시.

검토 초점: 오래된 경로 완료 정보, 취소/거절/무응답, 다른 모임에서 늦게 돌아온 콜백, 네트워크 실패와 재시도 중복, 경유지 또는 목적지가 바뀐 뒤 도착한 경로 비교.

검증: Python unittest 전체, 새 launcher/alternatives/context 테스트, Android assembleDebug/testDebugUnitTest. 모델과 실제 경로 제공자 실호출은 별도 표시한다.


## 실행 기록
- 기준 ZIP이 작업 중 0.14.4로 갱신되어 해당 소스를 다시 읽고 AI report_composer/Pleos observed context 수정까지 병합했다.
- 새 기능 테스트가 먼저 실패하는 것을 확인한 뒤 구현했다. 검토에서 확인한 빈 SDK 맥락, 원문 메시지 보존, 늦은 음성 결과, 완료 시간 보존을 수정했다.
- 기존 직접 메시지 전송을 유지하고 AI 요청 버튼을 추가하는 것으로 확정. 사용자가 자유롭게 메시지를 보낼 수 있어야 한다.
- Android 빌드/실제 마이크/Windows 설치는 완료하지 못했다. PC로 소스를 보내는 자동 승인 검토가 정확한 전송 대상 승인을 요구했고, 로컬 Gradle 다운로드도 Network is unreachable로 종료됐다.
- 완료 검증 기록은 INTEGRATION_VERIFICATION.md. ZIP은 APK 없는 소스 수정본이며 빌드 성공을 주장하지 않는다.
