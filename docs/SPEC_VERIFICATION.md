# 기획서 시나리오 검증 — 2026-11-14

기준 문서는 제공된 `1차 기획서.docx`의 3절, 4절 시나리오 A/B, 5-2 SDK 계획, 5-4 개발 범위 및 6-6 확장 계획이다. 표 안의 중첩 표까지 읽어 대조했다. 목표는 서로 다른 차의 위치·상황을 공유하고, 각 운전자의 선택으로 자기 차의 목적지 또는 경유지만 변경하는 것이다.

## 4절 요구사항과 근거

| 기획 요구 | 구현 및 자동 검증 근거 | 아직 필요한 차량 검증 |

| A1 / B1: 모임 생성, 초대, 공통 목적지 | `server.py` `/rooms`, `/join`; 개별 토큰·차량 식별자·목적지 좌표 제공. `test_scenarios.test_a_four_independent_origins_eta_and_tokens` | 네 차량에서 초대 수락/취소와 실제 내비 목적지 연결 |

| B2–3: 앞차와 떨어져도 자기 경로 유지 | 차량별 위치·개인 목적지·ETA를 별도 보관. 다른 차량의 이벤트가 개인 경로를 덮어쓰지 않는 HTTP 검증 | 실제 분기/이탈 좌표를 넣어 앞차 위치가 보이며 자기 내비 경로를 유지하는지 |
| B4–6: 앞차가 고른 휴게소를 뒤차에 전달, 동의 후 경유 합류 | 선택한 이름·주소·좌표·체류 시간을 rest 이벤트에 담음. `test_b_selected_rest_stop_and_decline_leave_current_destination_intact`; `JourneyScenarioTest.restOfferDoesNotChangeRouteUntilExplicitConfirmation` | 앞차/뒤차 모두 동일 좌표의 경유지 추가 확인, 목적지는 숙소 유지, 경유지 최대 2개 및 실패 처리 |
| 모든 변경은 운전자 확인 후 수행; 거절은 현재 경로 유지 | HTTP 테스트는 이벤트가 개인 경로를 바꾸지 않음을 확인. Android Journey 단위검사에 주차 2단계 선택, 휴식/목적지 거절, 중복 적용 알림 방지, 대기 제안 중 새 메시지 보존 포함 | 화면·음성 선택부터 실제 SDK 확인까지 연결된 전체 흐름, 운전 중 짧은 선택 및 P 이탈 시 상세창 제한 |

서버가 받는 `*_applied`는 인증된 클라이언트의 적용 확인 알림이다. 서버 단독으로 차량 SDK 성공을 증명하지 않는다. 공통 목적지 변경은 리더가 보낸 새 제안이며, 기존 참여자의 개인 안내 목적지나 ETA를 자동 변경하지 않는다.

## 이번 검증으로 수정한 문제

- 2,000개 이벤트 한도에서 목적지 변경 요청이 409로 거절되어도 공유 목적지가 먼저 바뀌던 순서를 수정했다. 거절 결과는 기존 목적지를 유지한다.
- “휴게소 가지 말자”가 휴식 제안으로 분류되던 규칙을 수정했다. 로컬 모델이 rest를 반환해도 명시적 거절은 일반 메시지로 보존한다.
- 개별 ETA에 출처, 안내 대상 좌표, 계산값의 나이를 붙였다. 새로운 heartbeat로 낡은 ETA의 수명을 연장하지 않으며, ETA가 null이면 관련 정보도 지운다.

## ETA 동기화 계약

| `/sync` 필드 | 의미 / 유효 범위 |
|---|---|
| `remaining_seconds` | 해당 출처가 산출한 남은 초, 정수 0–604800. null 또는 생략 시 이전 ETA 삭제 |
| `route_name` | 그 ETA의 개인 안내 목적지 이름. 모임 목적지와 다를 수 있음 |
| `route_latitude`, `route_longitude` | 그 개인 목적지 좌표. 한 쌍으로 제공, 유한 수, 위도 ±85/경도 ±180, (0,0) 제외 |
| `eta_source` | `road_estimate` 또는 `pleos`. 이전 클라이언트 호환을 위해 선택 사항 |
| `eta_age_ms` | 현재 남은 초를 만든 원래 계산값의 나이, 정수 0–60000. 서버는 수신 후 경과 시간만 추가함 |

`road_estimate`는 마지막 도로 산출값을 유지하며 새 경로 계산 시 갱신한다. `pleos` 및 구형 클라이언트 값만 수신 후 경과 초를 차감한다. 정차 중 도로 예상시간을 자동으로 줄이지 않는다. `eta_age_ms`가 60초 이상이면 ETA·출처·대상 표시를 모두 생략한다. 위치는 20초, 연결 표시는 15초 제한을 유지한다. 출처는 데이터의 계산 방식을 알리는 메타데이터이며 서버가 위치나 시간의 진실성을 인증하는 것은 아니다.

## 자동 검증 결과와 재현

2026-11-14 이 검증 작업에서 실행:

```sh
python -m unittest test_scenarios -v
# 7 tests, OK — 실제 로컬 HTTP 및 임시 SQLite

python -m unittest discover -v
# 71 tests, OK — 해당 시점 전체 Python 검사
```

추가 회귀 검사는 `test_expanded_server.py`, `test_message_intent.py`에 있다. 서로 다른 방의 토큰 차단, 리더 위임/탈퇴, 서버 저장 재로드 뒤 토큰·이벤트·재전송 중복 방지 유지, 오래된 위치/ETA 복원 금지를 검증했다. 서버 재시작 검사는 동일 SQLite를 새 `JourneyStore`로 읽는 저장 계층 재로드이며, 운영 중 프로세스 강제 종료/전원 차단 시험은 아니다.

`JourneyScenarioTest.kt`에 네이티브 상태 전이 검사 7개를 추가했다. 차량 SDK 또는 Android 화면/음성 재생을 실행하는 검사는 아니다. 최종 Android 빌드·단위검사 결과는 최종 인계 자료에 별도로 기록해야 한다. 이 문서의 Python 통과를 APK·실차 시나리오 통과로 해석하지 않는다.
