# Car Pairing v0.9 — Pleos 동행 앱

Pleos Connect용 네이티브 Kotlin Android 앱입니다. 동일 APK를 두 에뮬레이터에 설치하고 Python 서버 하나로 연결합니다. 프로젝트 두 개를 만들 필요가 없습니다.

## 실행

`Run-Two-Cars.cmd`를 실행합니다. Python 3.10+, Android SDK, Pleos Connect 2.1 시스템 이미지와 `Pleos_Connect_2_1` AVD가 필요합니다. 실행기는 기존 `Pleos_Pairing_Follower_1`을 우선 사용하고, 없으면 두 번째 AVD 설정을 생성합니다. 두 AVD는 각각 2GB/2코어로 실행하며 KYSDESKTOP의 기존 후발대는 host GPU를 사용합니다.

- 1번 차량: 판교, 위도 37.395 / 경도 127.110, emulator-5554
- 2번 차량: 잠실, 위도 37.510 / 경도 127.125, emulator-5556
- 공동 목적지 기본값: 강남역 2번 출구 37.49721 / 127.02805
- 실행 창은 2초마다 서로 다른 GPS를 공급합니다. 창을 닫으면 위치가 오래되어 공유가 대기 상태로 바뀝니다.

1. 각 차량에서 위치 권한과 동행 정보 공유를 직접 허용합니다.
2. 1번 차량에서 모임을 만들고, 2번 차량에서 6자리 코드 또는 QR로 참여합니다.
3. 공동 목적지를 수락합니다. 각 차량의 최신 위치와 개인 경로의 도로 예상시간이 공유됩니다. 더보기에서 Pleos SDK ETA로 전환할 수 있습니다.
4. 마이크가 없으면 메시지 직접 입력을 사용합니다. 전송 후 원문·정리문·분류 출처를 표시합니다.
5. `여정 도구`에서 휴식/주유/주차 계획, 개인 추천, 주차 기록, 모임 저장, 리더 변경을 사용합니다. 상세 입력은 P에서만 가능합니다.

기존 앱과 서명이 다르면 업데이트가 거부됩니다. 이전 개발 앱을 제거하면 그 앱의 저장 상태도 삭제되므로 먼저 확인하세요. 실행기는 서명 충돌 시 자동 삭제하지 않습니다.

## 구현 범위

| 기능 | 구현 방식 / 경계 |
|---|---|
| 별도 출발지·같은 목적지 | 에뮬레이터별 GPS, Pleos FusedLocation, NaviHelper 목적지, 외부 도로 ETA |
| 동행 위치·ETA·도착 상태 | 인증된 모임 동기화, 오래된 위치 숨김, 위치 공유 동의 |
| 지연·만차·휴게소 제보 | 직접 입력 또는 Pleos STT, 보수적 문장 정리, Pleos TTS |
| 만차 후 대체 주차 | 미도착 일행에 실제 시설 제안 → 운전자 수락 → NaviHelper 목적지 변경 |
| 같은 휴게소 / 주유소 | 실제 장소 좌표 공유, 각 차량이 수락 후 native 경유지 반영 확인 |
| 경유·정차 시간 비교 | 외부 도로 경로 + 입력한 체류 시간. 실시간 교통·기존 native 경유지 미포함 |
| 주차 후 도보 | 주차장→공동 목적지 도보 예상시간. 차량 GPS로 보행자를 추적하지 않음 |
| 개인 선택 추천 | 동의한 사용자의 실제 수락 횟수·최근 이력으로 장소 순위. 신경망 재학습이나 임의 경로 이탈 자동 학습 아님 |
| 주차 층·구역·메모 | 내 기록 저장·조회·삭제, 최신 위치가 없으면 위치 없이 명시적으로 저장 |
| 모임 저장·다시 시작 | 내 목적지 템플릿으로 새 모임 생성. 과거 일행 자동 재가입 없음 |
| QR·근처 모임·차량 번호 | 정확한 초대 URI, QR 이미지 읽기, 공개 동의한 3km 내 최신 모임. Bluetooth 검색 아님 |
| 리더 넘기기·공유 목적지 | 현재 리더 권한 확인, 연결 차량에 위임, 일행별 목적지 수락 |
| 재시작 복구 | SQLite 모임/인증/이력 저장, 앱 상태 복구. 재시작 후 오래된 GPS/ETA 재사용 없음 |

## Pleos와 외부 서비스

| 사용처 | 제공자 | 사용 이유 / 제한 |
|---|---|---|
| 차량 기어 | Pleos Vehicle 2.3.2 | P 상세 입력 구분 |
| 실제 내비 안내·경로 반영·ETA | Pleos NaviHelper 3.0.5 | 목적지/경유지 SDK 요청 및 반영 조회 |
| 차량 위치 | Pleos FusedLocation 1.1.3 | 차량별 좌표와 위치 신선도 |
| 음성 입출력 | Pleos STT/TTS 3.3.1 ON_DEVICE | HYBRID 인증 정보 없이 기기 내 모드 |
| 앱 도로 배경 | OpenStreetMap 타일 및 지역 도로 데이터 | Pleos 기본 내비의 흰 배경과 별개로 앱에서 도로 표시 |
| 장소 검색 | OSM Overpass, 지역 OSM 스냅샷 | 기본 SDK만으로 제공되지 않은 주차/휴식/주유 시설 목록 |
| 자동차·도보 경로 시간 | FOSSGIS / OSRM | 외부 도로 경로 계산. 실시간 교통 없음, 공개 서비스 가용성 보장 없음 |
| 선택적 장소 검색 | Kakao Local API | `KAKAO_REST_API_KEY` 설정 시 사용. 이 PC에는 키가 없어 실호출 미검증 |
| 선택적 상황 의도 분류 | Ollama Qwen3:4b | 현재 Pleos 2.1 릴리즈에서 LLM SDK 제거 안내. 별도 로컬 분류를 사용하며, 모델 오류 시 표시된 규칙 분류로 전환 |
| 초대 QR | ZXing 3.5.3 | 외부 서버 없이 기기 내 QR 생성·읽기 |

지역 스냅샷은 강남 주변 주차장 44곳(2026-11-12), 경기 휴게소/쉼터 4곳(2026-11-12), 강남 주변 실제 주유소 노드 6곳(2026-11-13)입니다. 전국 데이터가 아닙니다. OSM은 © OpenStreetMap contributors / ODbL이며 가격·영업·빈자리·진입 방향을 보장하지 않습니다. 원본 URL은 JSON에 보존했습니다.

앱 외부 지도는 동작하더라도 Pleos 기본 내비 지도 서버/라이선스 문제 자체를 해결했다는 뜻은 아닙니다. SDK 경유지 조회가 이름만 있고 좌표 0,0을 반환하는 경우 이름 일치로 확인하며 좌표까지 읽어 검증했다고 표시하지 않습니다.

## 서버와 개발

```powershell
python server.py
# 선택적 로컬 AI:
ollama pull qwen3:4b
ollama serve
# 자동검사:
python -m unittest discover -v
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

기본 서버 주소 `127.0.0.1:8765`, 에뮬레이터에서 `adb reverse tcp:8765 tcp:8765`로 연결합니다. `CAR_PAIRING_DB`로 SQLite 경로, `CAR_PAIRING_OLLAMA=0`으로 규칙 분류만 사용하도록 설정할 수 있습니다. 라우팅 주소는 `ROUTING_CAR_URL`, `ROUTING_FOOT_URL`로 교체할 수 있습니다. 공개 라우팅은 프로세스 전체 초당 1회 제한과 캐시를 사용합니다.

Android Studio 또는 VS Code에서 폴더를 엽니다. 빌드 환경은 JBR Java 25, Gradle 9.3.1, AGP 9.1.1, SDK 37.0 / build-tools 36.0.0입니다. `local.properties`에 자신의 `sdk.dir`을 설정하세요. APK는 `app/build/outputs/apk/debug/app-debug.apk`입니다.

SQLite에는 모임 접근 토큰과 개인 기록이 포함됩니다. 실행 중 생성된 DB/로그/앱 세션을 다른 팀원에게 배포하지 마세요. 배포 ZIP에서는 제외합니다. 이 앱은 로컬 시연용이며 여러 실제 PC/기기를 연결하는 HTTPS 서비스·계정 인증·운영용 푸시 서버는 별도 구축이 필요합니다.

실차, 실제 마이크 사투리 인식 품질, 실시간 주차 재고, 교통 반영, Gleo/HYBRID 인증, 임의 경로 이탈의 자동 학습은 완료 항목이 아닙니다. 실제 검증 범위는 `VALIDATION.json`을 참고하세요.

## v0.9 지도·ETA·음성 검증

- 내 차 파란 카드 아래에 선택한 일행의 빨간 카드가 표시됩니다. `일행 N대`에서 여러 차량을 선택합니다.
- 기본 ETA는 FOSSGIS 도로 경로 예상입니다. `교통 미반영`과 산출 경과시간을 표시하며, 정차 중 시간만 지나도 남은 시간이 줄어드는 오류를 수정했습니다. 45초 후 갱신, 60초 이상 오래되면 대기로 표시합니다.
- Pleos SDK ETA는 메뉴에서 따로 선택합니다. 에뮬레이터의 예시 수치는 실시간 교통 예상이 아닙니다.
- 내 차량 도로 경로에는 이 앱에서 수락한 경유지를 포함합니다. 빨간 일행 경로는 그 차량의 개인 목적지까지 직행 미리보기이며, 일행 경유지는 제외라고 표시합니다.
- 실제 조회한 지도 타일을 디스크에 보관합니다. 장애 시 저장된 타일과 서울 남부·판교 지역의 실제 OSM 도로 데이터를 사용합니다. 이 대체 데이터는 전국 오프라인 지도가 아닙니다.
- 주차장 선택 후 NaviHelper 목적지 좌표 변경을 두 AVD에서 확인했습니다. 경유지 반영은 SDK 콜백을 기다린 뒤 공유하며, 에뮬레이터에서 17초 지연을 관측해 확인 한도를 60초로 조정했습니다.
- `더보기 → 음성 설정 · 재생 테스트`에서 이 차량의 음성 안내를 켜고 끕니다. 두 AVD를 한 PC에서 시연할 때는 한쪽만 켜서 음성이 섞이지 않게 합니다. 설정은 앱 재실행 후 유지합니다.
- TTS 안내를 중단한 뒤 SDK 중지 콜백을 받아야 STT를 시작하며, 반복된 동일 안내를 대기열에 중복 추가하지 않습니다. 이는 엔진 음질 개선을 증명하는 것은 아닙니다.
- Pleos 기기 내 STT/TTS 초기화와 TTS 재생 시작은 확인했습니다. 실제 마이크 인식률, 사투리·소음 성능 및 최종 청감 품질은 아직 검증되지 않았습니다.

최신 검증 범위는 `docs/VERIFICATION_20261114.md`, 기획서 대조는 `docs/SPEC_VERIFICATION.md`, 간단한 사용법은 `사용설명서.txt`를 봅니다.

이 Source ZIP은 소스 전용이며 APK를 포함하지 않습니다. 빌드 후 `app/build/outputs/apk/debug/app-debug.apk`를 `dist/CarPairing-Pleos-Scenarios.apk`로 복사해 실행합니다. KYSDESKTOP에는 빌드한 APK와 최신 실행기가 설치되어 있습니다.
